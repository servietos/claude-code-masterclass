## Processes
- A vacancy is opened by adding a row to the Vacancies sheet in Excel, with title, skills and languages (`hr-sources/process-notes.md`: line 7, Mon row)
- A chef handing in notice is the trigger that starts a vacancy row (`hr-sources/process-notes.md`: line 7, Mon row)
- Each vacancy gets its own row; a second vacancy for the bar was handled with a new row and the same steps (`hr-sources/process-notes.md`: line 12, Wed row)
- The vacancy record carries a Status column, which is set to Filled when the owner moves an internal candidate into the role (`hr-sources/process-notes.md`: line 13, Thu row)
- The vacancy owner receives the internal candidate list by email, with the list pasted from Excel (`hr-sources/process-notes.md`: line 11, Tue row)
- Internal candidates are identified by filtering the Staff Copy sheet by skill and typing matching names into the Internal Candidates column (`hr-sources/process-notes.md`: line 9, Mon row)
- The Staff Copy sheet is filled by copying employee skills from the HR assistant's employee list in Claude Desktop (`hr-sources/process-notes.md`: line 8, Mon row)
- Staff Copy rows can be out of date; two rows were found out of date on Tuesday and fixed by hand after asking the HR assistant again (`hr-sources/process-notes.md`: line 10, Tue row)
- The staff re-copy into Excel is repeated for every vacancy, because the HR assistant holds employee data but no vacancy data (`hr-sources/process-notes.md`: line 16, closing paragraph)
- The weekly open-positions summary is sent on Friday; it counts open vacancy rows and reads Days Open, and is emailed via Outlook (`hr-sources/process-notes.md`: line 14, Fri row)
- Days Open is the only number management asks for on vacancies (`hr-sources/process-notes.md`: line 16, closing paragraph)
- Recorded minutes per step: opening a vacancy row 5 minutes, re-copying staff 20 minutes, filtering and typing names 15 minutes, the second vacancy 40 minutes, the status update 10 minutes, the Friday summary 15 minutes (`hr-sources/process-notes.md`: lines 7 to 14, Minutes column)
- The notes cover one hiring week, 14 to 18 September 2026, recorded by Anna Schmidt (Restaurant Manager) (`hr-sources/process-notes.md`: line 3)

## Data structure
- No vacancy, opening, position, or requisition class, record, enum, interface, or property exists in Models.cs; the file defines only Employee and EmployeeCollection (`hr-mcp-server/Tools/Models.cs`: `EmployeeCollection`)
- Employee has no vacancy-related properties; its persisted fields are Id, FirstName, LastName, Email, SpokenLanguagesData, SkillsData, CurrentRole (`hr-mcp-server/Tools/Models.cs`: `Employee.CurrentRole`)
- EmployeeDbContext exposes a single DbSet, Employees of type Employee, and no vacancy set (`hr-mcp-server/Data/EmployeeDbContext.cs`: `EmployeeDbContext.Employees`)
- The Employee entity is mapped to the table named "Candidates" (`hr-mcp-server/Data/EmployeeDbContext.cs`: `EmployeeDbContext.OnModelCreating`)
- Storage is SQLite, configured from the connection string named "EmployeeDatabase" in appsettings.json, appsettings.Development.json, or environment variables (`hr-mcp-server/Data/EmployeeDbContextFactory.cs`: `EmployeeDbContextFactory.CreateDbContext`)
- Schema is created with EnsureCreatedAsync, so no EF Core migrations are applied at startup (`hr-mcp-server/Data/EmployeeDbInitializer.cs`: `EmployeeDbInitializer.InitializeAsync`)
- Seeding runs only when the Employees table is empty and inserts 8 Employee rows; the seed contains no vacancy rows (`hr-mcp-server/Data/EmployeeDbInitializer.cs`: `EmployeeDbInitializer.GetSeedEmployees`)
- Data/ contains three C# files and no JSON, CSV, or other data files (`hr-mcp-server/Data/`: `EmployeeDbContext.cs`, `EmployeeDbContextFactory.cs`, `EmployeeDbInitializer.cs`)
## Current implementation
- No vacancy, position, requisition, or job-opening type, tool, service, or method exists in the scanned files; every HR tool and service operates only on `Employee` records (`hr-mcp-server/Tools/HRTools.cs`: `HRTools`)
- `HRTools` is an internal class marked `[McpServerToolType]` and receives `IEmployeeService` and `ILogger<HRTools>` through its constructor (`hr-mcp-server/Tools/HRTools.cs`: `HRTools`)
- Five MCP tools are exposed, each marked `[McpServerTool]` with a `[Description]`: `ListEmployees`, `AddEmployee`, `UpdateEmployee`, `RemoveEmployee`, `SearchEmployees` (`hr-mcp-server/Tools/HRTools.cs`: `HRTools`)
- `ListEmployees()` takes no parameters and returns an `EmployeeCollection` holding the result of `GetAllEmployeesAsync` (`hr-mcp-server/Tools/HRTools.cs`: `HRTools.ListEmployees`)
- `AddEmployee` requires `firstName`, `lastName`, `email`, `currentRole`; `spokenLanguages` and `skills` are optional strings defaulting to `""` (`hr-mcp-server/Tools/HRTools.cs`: `HRTools.AddEmployee`)
- `AddEmployee` trims the four scalar inputs (null becomes empty string) and parses the two list inputs with `ParseCommaSeparatedString` (`hr-mcp-server/Tools/HRTools.cs`: `HRTools.AddEmployee`)
- `AddEmployee` returns the text "Employee with email '<email>' already exists." when the service reports a duplicate, and "Successfully added employee: <FullName>" on success (`hr-mcp-server/Tools/HRTools.cs`: `HRTools.AddEmployee`)
- `UpdateEmployee` identifies the target by `email` and takes optional `firstName`, `lastName`, `currentRole`, `spokenLanguages`, `skills` (all default null) (`hr-mcp-server/Tools/HRTools.cs`: `HRTools.UpdateEmployee`)
- `UpdateEmployee` changes `firstName`, `lastName`, `currentRole` only when the value is not whitespace, but replaces `spokenLanguages` and `skills` whenever the value is non-null, so an empty string clears those lists (`hr-mcp-server/Tools/HRTools.cs`: `HRTools.UpdateEmployee`)
- `UpdateEmployee` returns "Employee with email '<email>' not found." when no match exists, and "Successfully updated employee with email: <email>" on success (`hr-mcp-server/Tools/HRTools.cs`: `HRTools.UpdateEmployee`)
- `RemoveEmployee` takes a single `email` parameter and returns "Successfully removed employee with email: <email>" or "Employee with email '<email>' not found." (`hr-mcp-server/Tools/HRTools.cs`: `HRTools.RemoveEmployee`)
- `SearchEmployees` takes one `searchTerm` string and returns an `EmployeeCollection` from `SearchEmployeesAsync` (`hr-mcp-server/Tools/HRTools.cs`: `HRTools.SearchEmployees`)
- `ParseCommaSeparatedString` returns an empty list for null or whitespace input, otherwise splits on commas, trims each item, and drops empty items (`hr-mcp-server/Tools/HRTools.cs`: `HRTools.ParseCommaSeparatedString`)
- The HRTools class summary states that all modifications are temporary and reset when the server restarts (`hr-mcp-server/Tools/HRTools.cs`: `HRTools`)
- `IEmployeeService` declares five async methods: `GetAllEmployeesAsync()`, `AddEmployeeAsync(Employee)` returning bool, `UpdateEmployeeAsync(string email, Action<Employee>)` returning bool, `RemoveEmployeeAsync(string email)` returning bool, `SearchEmployeesAsync(string searchTerm)` returning `List<Employee>` (`hr-mcp-server/Services/IEmployeeService.cs`: `IEmployeeService`)
- `EmployeeService` depends on `EmployeeDbContext` and `ILogger<EmployeeService>`, and throws `ArgumentNullException` if either is null (`hr-mcp-server/Services/EmployeeService.cs`: `EmployeeService` constructor)
- `GetAllEmployeesAsync` reads `Employees` with `AsNoTracking`, ordered by `LastName` then `FirstName` (`hr-mcp-server/Services/EmployeeService.cs`: `EmployeeService.GetAllEmployeesAsync`)
- `AddEmployeeAsync` throws `ArgumentNullException` for a null employee, trims the email, checks for an existing record with an exact `Email ==` match, and returns false if one exists (`hr-mcp-server/Services/EmployeeService.cs`: `EmployeeService.AddEmployeeAsync`)
- `AddEmployeeAsync` calls `AddAsync` and `SaveChangesAsync` on success and logs the addition at Information level (`hr-mcp-server/Services/EmployeeService.cs`: `EmployeeService.AddEmployeeAsync`)
- `UpdateEmployeeAsync` throws `ArgumentException` for a null or whitespace email and `ArgumentNullException` for a null action; it loads the first record matching the trimmed email, returns false if none, otherwise applies the action, calls `SaveChangesAsync`, and logs (`hr-mcp-server/Services/EmployeeService.cs`: `EmployeeService.UpdateEmployeeAsync`)
- `RemoveEmployeeAsync` throws `ArgumentException` for a null or whitespace email, finds the record by trimmed email, removes it, calls `SaveChangesAsync`, and logs; it returns false when no record matches (`hr-mcp-server/Services/EmployeeService.cs`: `EmployeeService.RemoveEmployeeAsync`)
- `SearchEmployeesAsync` returns all employees when the term is null or whitespace; otherwise it loads all employees and filters in memory with a case-insensitive `Contains` across first name, last name, email, current role, each skill, and each spoken language (`hr-mcp-server/Services/EmployeeService.cs`: `EmployeeService.SearchEmployeesAsync`)
- `Program.cs` registers `EmployeeDbContext` with `AddDbContext` using `UseSqlite` and the connection string named `EmployeeDatabase`; the code comment says SQL Server (`hr-mcp-server/Program.cs`: `AddDbContext<EmployeeDbContext>`)
- `Program.cs` registers `IEmployeeService` to `EmployeeService` with `AddScoped` (`hr-mcp-server/Program.cs`: `AddScoped<IEmployeeService, EmployeeService>`)
- `Program.cs` configures MCP with `AddMcpServer().WithHttpTransport().WithToolsFromAssembly()`, so tools are discovered from the assembly and served over HTTP (`hr-mcp-server/Program.cs`: `AddMcpServer`)
- `Program.cs` runs `EmployeeDbInitializer.InitializeAsync(app.Services)` before `app.MapMcp()` and `app.Run()` (`hr-mcp-server/Program.cs`: `EmployeeDbInitializer.InitializeAsync`, `MapMcp`)
- `Program.cs` contains no authentication or authorization registration for the MCP endpoint (`hr-mcp-server/Program.cs`: `WebApplication.CreateBuilder`)
- None of the vacancy-adjacent write paths validate content beyond trimming and null handling; `AddEmployee` does not check email format or require non-empty names (`hr-mcp-server/Tools/HRTools.cs`: `HRTools.AddEmployee`)
